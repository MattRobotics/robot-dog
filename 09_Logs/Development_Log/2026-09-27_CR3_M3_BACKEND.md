# MATDOG CR3-M3 — Minimal production ServoBus actuator backend

Date: 2026-09-27

This gate introduces the production transport primitives required by the existing
`ActuatorBackend` interface, but deliberately does **not** connect them to Controller.

## Added

- `ServoBus::enableTorqueOn(id)`
  - operational timeout;
  - SCServo ACK must be 1 and status 0;
  - independent `TorqueEnable == 1` readback is mandatory.
- `ServoBus::writeGoalPosition(id, uint16_t)`
  - target must be 0..4095;
  - no signed wrap/modulo;
  - one `WritePosEx` call only;
  - conservative bring-up speed 40 / acceleration 10;
  - ACK/status checked.
- `ServoBusActuatorBackend`
  - delegates to the one existing Controller-owned ServoBus;
  - owns no UART;
  - exposes no SAFE_OFF wrapper.

## Still deliberately absent

- no Controller member/instance of the production backend;
- `ActuatorRuntime::begin(..., nullptr)` remains unchanged;
- no command surface can call `execute()`;
- no q0/geometry/limit admission is production-wired;
- no calibration permit is production-wired;
- global `hardware_motion_authorized` remains false.

Therefore this commit changes the available transport implementation but does not make physical
motion reachable from the running Controller. The first wiring of these primitives is part of the
separate first-motion activation gate and requires explicit current-session hardware authorization.
